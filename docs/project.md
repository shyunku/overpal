# palworld-helper-mod

팰월드 전용 서버에서 게임 데이터를 실시간으로 꺼내 게임 화면 위 오버레이로 보여주는 프로젝트.

## 목적

- 거점에 저장된 모든 아이템(상자 속 포함)을 실시간으로 조회한다.
- 플레이어 위치, 팰, 길드 같은 정보와 합쳐 게임 위 오버레이로 보여준다.
- 사용자와 친구가 함께 쓴다.

기존 방법으로는 거점 상자 속 아이템을 실시간으로 얻을 수 없어서 직접 만든다.

- 내장 REST API(8212): `info`, `players`, `metrics`, `settings`뿐이다.
- PalDefender REST(17993): 플레이어 위치, 팰, 인벤토리, 길드, 거점 일꾼 팰은 주지만 거점 구조물은 `"WIP"`이고 거점 상자 아이템은 없다.
- 세이브 파일 파싱: 실시간이 아니고, 현재 세이브 포맷(PlM)을 `palworld-save-tools` 0.24.0이 읽지 못한다.

## 용어

| 용어 | 설명 |
| --- | --- |
| 게임서버 | 팰월드 전용 서버(PalServer). |
| 모드 | 게임서버 프로세스 안에서 도는 UE4SS Lua 스크립트. 서버 메모리에서 거점 데이터를 읽어 JSON 파일로 쓴다. |
| 앱 | 게임 밖에서 도는 TS 기반 exe. 서버 부분과 클라 부분으로 구성된다. |
| 앱 서버 부분 | 모드 JSON과 PalDefender API를 합쳐 HTTP API로 제공한다. |
| 앱 클라 부분 | 서버 부분에 접속해 데이터를 받아 게임 창 위에 오버레이로 표시한다. 플레이어 PC의 팰월드와는 직접 소통하지 않는다. |

## 구조

```
[게임서버 + UE4SS + 모드 + PalDefender]
      │ base_storage.json (모드)        │ REST 17993 (PalDefender)
      ▼                                 ▼
[앱 서버 부분]  ── HTTP(토큰 인증) ──▶  [앱 클라 부분(오버레이)]
```

- 상자 내용은 이벤트로 전달된다(2026-10-12, #17). 모드가 컨테이너 변경 훅으로 바뀐 컨테이너만 다시 읽어 파일을 쓰고, 앱 서버가 파일 변경을 감지해 `GET /api/events`(SSE, 이벤트 이름 `storage`)로 클라에 밀어준다. 상자 변경은 1초 안팎으로 화면에 반영된다.
- PalDefender 데이터(플레이어 위치·인벤토리 2초, 길드 15초)는 푸시가 없어 폴링한다. 상자 변경 이벤트가 오면 내 인벤토리를 바로 다시 받아 함께 반영한다. 상자↔인벤토리 이동 중에 합계가 잠깐 빠지지 않게 하기 위해서다.

- 앱은 실행 옵션으로 `서버만`, `클라만`, `서버+클라` 3가지를 모두 지원한다.
- 게임서버를 띄우는 사람은 `서버+클라`, 친구는 `클라`로 실행한다.
- 게임서버 PC에서 게임서버와 앱 서버 부분이 둘 다 켜져 있어야 한다.
- 친구가 접속하려면 앱 서버 부분의 포트를 열거나 VPN을 써야 하며, 토큰 인증이 필수다.

### 모드 (`mod/PalHelperMod`)

- 서버 시작 30초 뒤부터 10초마다 전체를 다시 읽어 `base_storage.json`과 `status.json`을 모드 폴더에 쓴다.
- 그 사이에는 `PalMapObjectItemContainerModule:OnUpdateContents` 훅이 바뀐 컨테이너를 표시하고, 250ms마다 표시된 컨테이너만 다시 읽어 내용이 실제로 바뀌었을 때만 파일을 쓴다. 파일의 `seq`는 쓸 때마다 1씩 늘어난다.
- 모든 루프는 게임 스레드(`LoopInGameThreadWithDelay`)에서 돈다. 이유는 [cautions.md](cautions.md)의 모드 항목.
- 쓰기 중인 파일을 읽지 않도록 임시 파일에 쓰고 이름을 바꾼다.
- 읽는 방법과 객체 연결 구조는 [game-internals.md](game-internals.md)에 정리했다.
- 추적 범위(2026-10-12 결정): 위치(상자, 제작 건물 결과물 보관함, 길드 창고, 맵 줍기 아이템 등)별 아이템 개수와, 제작 건물에 걸린 주문 중 아직 만들지 않은 수량(무엇을 몇 개 더 만들지)을 추적한다.
- 개발용 탐색: 모드 폴더에 `probe.lua`를 넣으면 재시작 없이 다음 갱신 때 한 번 실행하고 결과를 `probe_out.txt`에 쓴다. 실행한 스크립트는 `probe.done.lua`로 이름이 바뀐다. `ENABLE_PROBE`로 끌 수 있다.

`base_storage.json` 형식:

```json
{
  "version": 1,
  "updatedAt": 1791744000,
  "seq": 12,
  "storages": [
    {
      "containerId": "D5A2D09F-406C826E-1BF0498E-5129A3C4",
      "group": "550A88ED-45A08C78-E5FA84BC-74F75B00",
      "kind": "chest",
      "modelClass": "PalMapObjectItemChestModel",
      "buildObjectId": "ItemChest",
      "location": { "x": -354871.4, "y": 259974.6, "z": 3986.5 },
      "slotCount": 10,
      "items": [{ "index": 0, "item": "Stone", "count": 81 }]
    }
  ]
}
```

- `group`: 길드 ID. PalDefender `/guilds`의 길드 ID와 같다.
- `kind`: `chest`, `guildChest`, `production`, `dropped`, `pickup`, `guildStorage`, `other`. 앱은 여기에 내 인벤토리(`inventory`, PalDefender `/items`의 `Items`·`Food`)를 더해 거점 합계에 포함한다. `dropped`는 플레이어가 바닥에 버린 아이템이다. `pickup`은 맵에 배치된 줍기 아이템(돌, 나뭇가지, 열매 덤불)이며 앱의 합계에서 제외한다.
- `item`: 게임 내부 아이템 ID. 표시 이름 변환은 앱에서 한다.
- `location`: 건설한 건물과 바닥에 버린 아이템에 있다. `pickup`, `guildStorage`에는 없다.

### 앱 (`app/`)

- 프레임워크: **Tauri v2**. 투명 창과 Windows 블러(Acrylic/Mica)를 지원하는 가장 가벼운 선택지로 정했다(2026-10-12). Electron은 무겁고, 더 가벼운 프레임워크는 블러를 지원하지 않는다.
- 화면: Vite + React + TS. palworld-helper와 같은 스택이다.
- 역할 분담(2026-10-12 결정):
  - **Rust**: 앱 서버 부분의 최소 기능만 둔다. HTTP 서버, 토큰 검사, 모드 JSON 읽기, PalDefender 중계. 데이터 가공은 하지 않는다.
  - **TS**: 데이터 합치기, 아이템 이름 변환, 오버레이 표시 등 로직 전부.
- 실행 옵션: `--mode server`(창 없이 API만), `--mode client`(오버레이만, 원격 서버에 접속), `--mode both`(둘 다).
- 오버레이는 게임이 테두리 없는 창 모드일 때 위에 표시된다. 전체화면 독점 모드에서는 보이지 않을 수 있다.

#### 오버레이 (2026-10-12 시안 확정, `docs/designs/overlay-mock.html`)

- 창 구성: 메뉴 바, 아이템 수량, 미니맵, 설정을 각각 별도의 작은 창으로 띄운다. 창이 없는 곳의 클릭은 그대로 게임으로 간다.
  - 메뉴 바: 화면 오른쪽 위(오른쪽·위에서 QHD 5px). 연결 상태 원, 미니맵/아이템 수량/설정 토글.
  - 아이템 수량: 레이아웃 3종(사이드 패널 / 미니 HUD / 전체 격자)을 제목줄 오른쪽 토글로 전환. 기본은 사이드 패널, 위치는 팰 슬롯 위(왼쪽 아래 기준, 모드를 바꾸면 위로 늘어남). 닫기는 메뉴 바로만 한다.
    - 합계에 내 인벤토리를 포함한다. 사이드 패널 목록은 7줄 높이로 고정하고 안에서 스크롤한다.
    - 검색 중에는 가지지 않은 아이템도 수량 0(빨간색)으로 함께 보여 준다. 가진 것(수량순) 다음에 안 가진 것(이름순). 한글 이름이 없는 옛 아이템은 제외한다. 시안: `docs/designs/item-search-mock.html`.
  - 미니맵: 원형, 오른쪽 위 퀘스트/거점 패널 아래. 지도 불투명도 80%, 비네트 그림자. 내 위치와 거점 표시. 닫기 버튼이 없고(메뉴 바로만 끔) 마우스를 항상 통과시킨다. 커서가 보이는 동안(조작 가능 상태)에는 숨기며, 창 위치 편집 중에만 보이고 끌어서 옮길 수 있다.
  - 설정: 창 위치 편집(편집 중에만 창을 끌어서 이동)과 초기화.
- 크기: 1920×1080 기준 "스테이지 단위"로 설계하고 화면 높이에 비례해 확대/축소한다(QHD에서 1.333배, Windows 배율도 반영). 아이템 수량 창은 배율 0.49, 설정 창은 그 1.25배.
- 배경: 블러 항상 켬(Windows 예전 Acrylic), 어두운 틴트 25%로 고정. 자세한 이유는 [cautions.md](cautions.md).
- 폰트: Oxanium(영문·숫자) + Noto Sans KR(한글), 앱에 내장.
- 표시 규칙: 팰월드 창이 보이면 표시한다. 최소화되거나 꺼지면 숨기고, 다른 창들이 팰월드 창을 10% 이상 가리면 숨긴다(모니터·포커스와 무관). 이 앱의 창과 클릭 통과 창(다른 앱의 오버레이)은 가림 계산에서 뺀다. 오버레이는 팰월드가 있는 모니터에 뜬다.
- 조작: 게임이 커서를 숨기고 있을 때(플레이 중)는 클릭 통과, 커서가 보일 때(ESC·인벤토리)만 조작 가능. 다른 앱이 앞에 있으면 항상 조작 가능으로 본다(그 앱이 타이핑 중 커서를 숨기는 것은 게임 조작이 아니다).
- 창 위치·열림 상태·아이템 보기 모드는 앱 설정 폴더의 `layout.json`에 저장한다. 위치는 화면 가장자리 기준 스테이지 단위라 해상도가 바뀌어도 같은 자리에 온다.
- 아이템 이름과 아이콘: `app/src/data/itemTable.json`(게임 ID → 한글 이름, 아이콘 파일)과 `app/public/icons/items/`. `scripts/build_item_table.py`로 만든다. 이름은 게임의 한국어 아이템 이름 테이블에서, 아이콘은 palworld-helper의 아이콘(96px로 축소)에서 가져온다. 이름이 없는 옛날/미사용 아이템은 ID로 표시하며, 필요하면 `scripts/item_names_manual.json`에 직접 넣는다.

## 알려진 위험

- UE4SS를 서버에 설치하면 접속자가 새 캐릭터 생성 창을 만나는 버그가 보고되어 있다(UE4SS-RE/RE-UE4SS #836, #1091, #405). 현재 환경(1.0.5 + 2281fa31 + PalDefender)에서 기존 캐릭터 재접속은 정상임을 확인했다. 새 플레이어 첫 접속은 확인하지 않았다.
- 게임 업데이트로 클래스나 필드 이름이 바뀌면 모드가 깨질 수 있다.
- 실제 월드(협동 세이브)를 전용 서버로 옮기면 호스트 캐릭터 ID가 맞지 않는 문제가 있다. 현재 세이브 포맷을 읽는 ID 변환 도구가 없어서 이전은 보류 중이다.
